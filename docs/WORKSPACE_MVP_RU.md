## Реальные функции

- Вход/выход, обновление сеанса, выбор доступного дома — существующие операции Core.
- Дом, этажи, комнаты, устройства, сценарии — существующие чтения и компоненты.
- `/devices`: поиск по названию устройства/комнаты и фильтр по reported online.
- `/automations`: `GET /automations`, с обязательной фильтрацией по выбранному
  `house_id`; enabled, триггер, условия, упорядоченные действия и задержки.
- `/events`: `GET /events?house_id=…&limit=100`, проверка принадлежности дому,
  время, код события, entity ID. Произвольный payload и глобальные события не выводятся.
- Ошибки чтения правил/журнала изолированы от главной и комнат. 403 — ошибка доступа,
  а не пустой успешный ответ. При ошибке обновления старые записи не показываются
  как актуальные. Обновление вручную; время загрузки не означает время измерения.
- Новые разделы в mock честно требуют Core, не подставляют выдуманные правила.
- Русские тексты экрана входа, комнат, устройств, сценариев, настроек, ошибок,
  доступных подписей и заголовков. Имена, ID и неизвестные коды из Core не переводятся.
  Исторические имена и описания demo-fixtures сохранены; главная уже имеет русское
  представление этих названий. Это остаётся ограничением полной локализации демо.
- Мобильная навигация сохраняет четыре основных экрана и доступное меню «Ещё»
  для устройств, правил и журнала; меню закрывается при переходе. Светлая/тёмная/системная темы сохранены.

## Управление и физическая безопасность

Существующий `createRelayControl`, проверка `device.control` + `device.read`,
проверка online/capability, единственная отправка POST, idempotency key,
чтение receipt до applied/failed/timed_out и отмена при смене дома/сеанса сохранены.
Software relay не отключены этой веткой. Ни одна команда реальному оборудованию
в ходе работы не отправлялась. Тесты новых разделов выполняют только GET после login.

Firmware v0.12 закрывает физическое управление. Проверенный Core выполняет
`PhysicalBindingGuard.require_active`, `require_command_contract` и transport
`authorize_command` перед отправкой. Web не ослабляет эти проверки.
В общедоступном DeviceRead нет надёжного признака software/physical и endpoint
физического допуска. Поэтому Web не угадывает класс по имени, online или metadata,
не обещает предварительное определение допуска и оставляет решение Core.
Кнопка может быть доступна по правам, но сервер отклонит закрытый physical command.
Отказ отображается, автоматического повтора нет; успешное чтение состояния
не объявляется подтверждением команды. Для предварительной блокировки именно
физических кнопок нужен отдельный авторитетный Core capability contract.

Просмотр enabled-автоматизации не подтверждает её исполнение. Редактирование,
включение/выключение автоматизаций, запуск Core-сценариев, создание домов/комнат
и onboarding не реализованы этой веткой. Существующие mock-команды остаются симуляцией.

## Запуск

```sh
npm ci
npm run dev
# http://127.0.0.1:5173 — только mock, сброс при перезагрузке
```

Для своего локального Core создайте игнорируемый `.env.local`:

```dotenv
VITE_DATA_MODE=core
VITE_API_URL=/core-api
CORE_DEV_PROXY_TARGET=http://127.0.0.1:18000
```

Перезапустите Vite, войдите существующей учётной записью. Пароли и токены не
записывайте в `.env`/репозиторий. Сеанс хранится в памяти вкладки. Proxy — только
локальная разработка; production-маршрутизация и deployment не добавлены.

## Проверки и снимки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:core
node scripts/capture.mjs
```

Core browser suite использует перехваченные контрактные ответы, **не живой Core**.
Live/confirmed-live suites сохранены, но не запускались: они требуют отдельной
тестовой инфраструктуры. Реальные аккаунты/оборудование этой задачей не изменяются.

CI `Web checks` выполняет статические проверки, unit и mock/Core-contract browser
suites на 1440, 1024, 834, 390, 320px. Отдельная job снимает base main и новую ветку
на 1440, 390 и 320px, обе темы, главная/комнаты/настройки; артефакт
`before-after-screenshots`, с manifest и пометкой mock simulation.

Локальный Chromium в агентской среде блокируется на создании Unix socket
(`Operation not permitted`); облачный браузер не достигает localhost этой среды.
До получения успешного CI визуальные проверки и снимки считаются **не выполненными**.
Не путать запуск Vite/успешную сборку с проверкой браузером.

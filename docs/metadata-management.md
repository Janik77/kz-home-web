# Названия и размещение: этап 2

## Что доступно владельцу

- Настройки: переименовать дом, отдельно от его часового пояса.
- Комнаты → «Названия этажей»: переименовать этаж.
- Страница комнаты: изменить название и выбрать этаж этого дома.
- Устройства → Подробнее: изменить название и выбрать комнату этого дома.

Это метаданные, не команды устройству. Переименование и перемещение не включают и не выключают реле. Перенос между домами, удаление, дублирование и расширение истории не входят в этот этап. Существующие ограничения Core на привязку физических устройств сохраняются.

## Конфликты и неопределённый результат

Каждая форма читает свой `metadata_revision`. PATCH передаёт `expected_metadata_revision`; новый Core требует его обязательно. Отсутствие счётчика у старого Core означает только просмотр, не подстановку версии 1.

После записи Web проверяет ответ и повторный GET: идентификатор, новое название, родителя и ровно следующий счётчик. Ошибка или потерянный ответ блокируют повторную запись: черновик остаётся в форме. «Сравнить с Core» показывает обе версии. Можно принять серверную либо явно оставить черновик для новой версии, проверить его и отдельно сохранить. Автоматической перезаписи и повторного PATCH нет.

При смене аккаунта/дома запросы отменяются, кэш изолирован. Старая загрузка не должна заменить подтверждённые изменения. Если запись проверена, но общий список не обновился, интерфейс сообщает это отдельно и не предлагает повторить запись.

## Разделение счётчиков

Название дома использует только `expected_metadata_revision`. Часовой пояс продолжает использовать только `expected_timezone_revision`. Эта форма никогда не отправляет смешанную правку. Изменения MQTT-состояния не являются версией метаданных.

## Проверки

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npx playwright test --config playwright.metadata.config.ts
python -m unittest discover -s e2e -p test_metadata_fixture_contract.py -v
```

`metadata-ui.spec.ts` использует явно обозначенные перехваченные ответы: desktop/mobile, светлая/тёмная темы, все четыре формы, конфликт, сохранение черновика, отсутствие горизонтальной прокрутки и axe. Это НЕ тест реального Core.

`metadata-live.spec.ts` предназначен для существующего CI-owned `automation-live-runner.py` с `LIVE_METADATA_ONLY=1`: настоящий PostgreSQL/Core и MQTT TLS программное реле, изменение всех четырёх сущностей, конкурентная правка, 409 на старой версии, запрет resident/foreign, повторный GET и ноль MQTT-команд. Видео и изображения сохраняются в CI. Нужна точная версия Core с обязательным CAS; до её проверки этап не считается готовым.

Физические устройства не используются. Постоянный стенд, его данные и профиль не изменяются этим тестом.

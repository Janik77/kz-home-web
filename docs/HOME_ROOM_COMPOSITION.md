# Home / Room: этап визуальной приёмки

Основа: Web #20 `c2c4fa89a0da3652e8e0cca3629300ecfd7e658f`.
Live-контракт: Core #42 `82653a849d2b61479de1c3bb4d74e7f388523667`.
Новая композиция ограничена главной, комнатой и их оболочкой. Другие страницы
сохраняют прежнее оформление до отдельной визуальной приёмки владельцем.

Главная: быстрые сценарии, управление устройствами, компактные комнаты и важные
события. Для малого дома используется отдельная плотная desktop-сетка. Комната:
краткое состояние, устройства, связанные сценарии. Нет фотографических заглушек
или постоянной карточки отсутствующего датчика. Токены пилота ограничены классом
`app-shell--everyday`, обе темы и существующая нижняя навигация сохранены.

## Посмотреть отдельно обозначенную демонстрацию

Нужны Git и Node 24/npm. Команды выполняются в новом каталоге, существующий
checkout пользователя не изменяется:

```sh
git clone --branch feat/home-room-composition https://github.com/Janik77/kz-home-web.git kz-home-web-pilot
cd kz-home-web-pilot
git rev-parse HEAD
npm ci
VITE_DATA_MODE=mock npm run dev -- --host 127.0.0.1 --port 5173
```

Для воспроизводимости перед `npm ci` можно выполнить `git checkout --detach`
с точным SHA, указанным в итоговом отчёте PR #21.

Открыть `http://127.0.0.1:5173/?demo=one`, `?demo=many` или `?demo=unavailable`.
Комната: `http://127.0.0.1:5173/rooms/living?demo=one` (те же три набора).
`one`: одно реле; `many`: 10 приборов и четыре комнаты;
`unavailable`: недоступный прибор, пустая кухня, без сценариев и событий.
Для просмотра пустой комнаты: `/rooms/kitchen?demo=unavailable`.
Тема переключается кнопкой в верхней панели. Это симуляция в памяти,
изменения сбрасываются перезагрузкой; запросы к Core не выполняются.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:core
node scripts/capture-home-room.mjs
```

Последняя команда открывает настоящий Chromium и создаёт 24 PNG в
`test-results/home-room-matrix`: 2 страницы × 390/1440 × две темы × три набора.
Проверяет отсутствие горизонтального переполнения и ошибок страницы.
Снимки делаются после загрузки шрифтов и завершения CSS-переходов.
На Linux необходимы системные зависимости Chromium; CI устанавливает их
штатным Playwright installer. Локальный ограниченный sandbox может запретить
запуск браузера; это не повод подменять скриншоты HTML-макетом.

## Реальный Core — отдельный режим

Только для уже запущенного изолированного Core на loopback:

```sh
CORE_DEV_PROXY_TARGET=http://127.0.0.1:8000 VITE_DATA_MODE=core VITE_API_URL=/core-api npm run dev -- --host 127.0.0.1 --port 5173
```

`?demo=...` не переключает этот режим и не подменяет данные. Для автоматического
полного software-only стенда использовать workflow `Live Web Core MQTT software
relay` этой ветки: точный Core #42, PostgreSQL, MQTT TLS, браузер, реальные
ACK/state и SQL-корреляции. Core launcher здесь не изменён; совместимость его
списка разрешённых Web SHA с новым пилотом не заявляется.

Запись `live-software-home-control.webm` начинается после авторизации и
заканчивается до смены учётных записей. Она показывает реальное программное
реле: Выключено → ожидание при задержанном ACK → Включено после applied и
обновления данных. Это встроенная запись браузера, без синтетических кадров,
паролей и автоматического подтверждения до ACK/state.

## Сохранённые ограничения

- Core не предоставляет избранное: на главной честно показаны «Устройства дома»;
  демо использует свой существующий признак favorite.
- Сценарий из реального дома ведёт к существующему экрану явных шагов. Быстрая
  кнопка не отправляет скрытый POST и не выполняет все действия автоматически.
- Известное реле имеет одно действие по последнему состоянию. Неизвестное
  состояние не угадывается; eligibility/права и закрытые gates сохраняются.
- Нет optimistic ON. Неизвестный исход, ошибка, недоступность и возможность
  новой команды остаются видимыми; ACK/state не доказывает физическое OFF.
- Заголовок сообщает о полученных данных, а не обещает постоянное соединение.
  Обновление ручное. Технические подробности доступны на прежнем экране устройств.
- На главной события ограничены явно известными типами; остальные в журнале.
- Черновики, revision/409, ограниченная история запусков и подтверждение новой
  подготовки сохранены; отсутствие локальных unknown не доказывает безопасность.
- 10 избранных приборов на 390 px образуют длинный прокручиваемый список с
  читаемым управлением; это не скрывается сокращённым демонстрационным наполнением.
- Зеленый CI не является визуальной приёмкой пользователя. Остальные разделы
  намеренно не переработаны; hardware, main, production и Core не изменяются.
